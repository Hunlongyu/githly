# Githly 软件开发文档

日期：2026 年 11 月 6 日  
状态：原生客户端开发中，完整功能与性能验收待进行  
软件名称：Githly（品牌名首字母大写）  
优先平台：Windows，保留跨平台能力  
界面技术：Rust 与 gpui-kit，使用默认后端，gpui-fast 保留为可选项  
Git 来源：用户系统中已安装的 Git

本软件服务于由 AI 执行代码修改、提交、合并和同步的开发方式。用户通过面板查看项目状态、更改规模、分支和提交历史，在需要了解具体变化时打开简单的左右 Diff。产品不建立逐行代码审查流程。

当前实现覆盖与验证结果见 [原生开发进度](native-development.md)；本文中的完整功能和性能目标是后续验收要求，不代表已经全部实现。

界面参考 VS Code 2026 Light / Dark 配色和紧凑工作台样式：中性背景、分层面板、细边框、低对比选中背景和蓝色焦点强调，使用 Kit 原生控件与图标。

设置使用居中独立模态弹窗，不展开在标题栏下方、不压缩历史和 Diff 区域。右上角齿轮和 Ctrl+, 打开，Esc、关闭按钮或“完成”关闭，关闭后恢复焦点。外观与 Git 路径集中展示，设置即时保存；弹窗打开时不能操作背景工作区。

## 产品目标

让用户快速回答以下问题：

- 当前项目或工作目录存在什么变化，改动规模有多大。
- 当前工作目录在哪个分支，其他本地与远程分支是什么状态。
- 最近提交了什么，分支之间如何分叉与合并。
- Stash 中保存了哪些内容。
- 某次历史提交修改了哪些文件，这些文件具体改变了什么。

主界面以状态、列表、统计和历史关系为主。普通启动时显示项目选择页。打开项目后显示更改和提交历史，用户选择提交时展示第一个变更文件的左右差异。

界面流畅和大型项目支持是首版要求。用户已有项目包含 **19,685 条提交历史**，该规模作为实施阶段必须覆盖的真实仓库基线，不作为支持上限。后台 Git 查询、刷新和解析不能阻塞 UI 线程；历史列表与关系图均须支持虚拟渲染和分批加载。

## 功能范围

### 保留功能

| 模块 | 范围 | 边界 |
| --- | --- | --- |
| 项目 | 添加已有本地仓库、最近项目、项目切换、状态概览 | 不提供 clone、init |
| 更改 | 文件清单、修改类型、增删行数、已暂存与未暂存状态、未跟踪文件 | 不提供暂存、取消暂存、提交或丢弃操作 |
| 分支 | 本地分支、远程跟踪分支、当前分支、上游关系 | 远程数据来自本地已知引用 |
| 分支切换 | 明确操作入口，用于切换工作目录的分支 | 浏览分支不触发切换 |
| 历史 | 普通列表与圆点线条关系图、提交信息、涉及文件 | 不提供历史编辑 |
| 文件 Diff | 从历史提交进入，展示该次提交修改文件的左右差异、行号、增删颜色与基础语法高亮 | 不提供独立分支比较或任意版本比较面板 |
| Stash | 列表、描述、时间、涉及文件、简单 Diff | 仅查看；不创建、恢复、删除 |
| Worktree | 展示已有工作目录、路径、分支、更改状态 | 建议纳入首版；不创建或删除 worktree |
| 仓库异常状态 | 展示冲突、合并中、变基中、内容不可用等状态 | 不提供冲突解决或流程继续、终止操作 |

### 不纳入的功能

- Commit、暂存、取消暂存、丢弃文件更改。
- Pull、Push、Fetch、自动同步及远程认证配置。
- Merge、Rebase、Cherry-pick、Reset、Revert 等写入操作。
- Stash 创建、恢复、弹出、删除。
- 冲突解决、三方合并编辑器。
- 逐行评论、审阅批注、已读与未读文件、审阅进度。
- 审阅检查点、从上次审阅位置继续、审阅任务管理。
- 本地活动时间线、操作回放。
- 独立的“比较”按钮、分支比较面板、任意版本选择和共同祖先比较流程。
- 首版不接入 AI 服务生成总结或识别任务归属。

提交历史仍然保留。提交历史展示仓库中的提交与父子关系；本地活动时间线展示操作事件，两者不是同一功能。

## 信息架构与交互

### 主界面

采用紧凑的桌面工具布局。顶部依次展示项目选择器、worktree 按钮、分支选择器和少量状态信息。日常使用以少量项目为前提，不建设项目总览侧栏。

左侧为当前项目的“更改 / Stash”面板，右侧以提交历史为主。两者同时可见，不需要在更改与历史之间切换整页。历史支持关系图与普通列表。

项目菜单展示最近项目。仓库有其他可打开的工作目录时，顶栏显示 worktree 下拉菜单，列出路径、分支和更改状态。当前目录带勾选标记，选择其他目录即可打开。分支菜单提供搜索和可折叠的本地、远程分组，标记当前分支。

分支浮层约 340 px 宽，搜索框固定在顶部；分支列表最高 420 px，窗口较小时自适应缩小，超出部分通过滚动查看。两组可独立折叠，显示筛选后的数量；当前分支带勾选和“当前”标记，长名称截断并提供完整名称悬停提示。按 Git 引用命名空间区分本地和远程，排除远程 HEAD 别名，不提供新建分支入口。

文件数量和增删行数使用列表标题中的紧凑文字，不使用大数字卡片、项目标题区或审阅完成率指标。

主窗口不设置底部全局状态栏。项目完整路径与本地读取时间保留在项目入口的悬停提示中，保留完整日期与秒。Git 正常时不显示常驻状态文字；Git 缺失、读取失败等异常在加载入口或相关面板中就近显示原因及可用操作，不依赖底栏。

加载项目或切换历史浏览范围时，历史列表使用完整高度。选中提交后，下方详情区展示首个变更文件的 Diff，点击其他文件可切换内容。关闭详情区后，历史恢复完整高度。更改、Stash 的文件预览共用该详情区域。

### 视觉与桌面交互

产品是 Rust / gpui-kit 原生桌面客户端。界面使用真实仓库数据，按桌面应用的窗口、焦点和键盘交互方式设计；开发进度与未实现能力在开发文档中说明。

- 保持紧凑工具栏、左侧文件列表、右侧历史及下方 Diff 的桌面分栏结构，不采用网页导航或卡片式首页。
- 标题栏右上角提供最小化、最大化 / 还原、关闭按钮，使用统一尺寸的系统风格图标；关闭按钮悬停和按下时标红。双击标题栏空白处切换最大化与还原。正式客户端调用原生窗口 API，最小化进入系统任务栏，关闭只关闭当前应用窗口。窗口控制按钮与项目 / 分支等交互区域不参与标题栏拖动。
- 提供深色和白色两套完整主题，顶部可切换并记住选择。菜单、弹窗、选中状态、关系图、滚动条和 Diff 增删颜色随主题更新；切换主题保留当前提交、文件和浏览位置。
- “更改 / Stash”和“关系图 / 列表”均为互斥分段按钮组，始终保留一个选中项。切换时选中底块平滑滑动，文字颜色同步过渡；快速连续切换从当前动画位置衔接。默认使用轻微动效，设置提供“跟随系统 / 轻微 / 关闭”；仅控制应用内动效，不更改系统设置。
- 历史关系图切换为列表时，连线和圆点在约 180 ms 内淡出，关系图列同步收起；切回时平滑展开与淡入。设置弹窗仅淡入淡出，不使用夸张位移或回弹。关闭动效时立即到达最终状态。
- Windows 优先采用 Segoe UI Variable / Segoe UI 与微软雅黑 UI，正文约 12–13 px，辅助信息约 11 px；等宽字体仅用于代码及提交标识。图标使用统一的 SVG 线条规格和固定尺寸，按钮通过布局居中对齐，不用 Unicode 字符模拟图标或用空格定位。
- 两处分隔线支持鼠标拖动，调整文件面板宽度与详情高度；聚焦分隔线后也可用方向键调整，保留上次设置。
- 支持 Ctrl+O 打开项目、Ctrl+F 搜索历史、Ctrl+B 打开分支菜单、F5 重新读取本地状态。历史与文件列表支持方向键及 Home / End 选择；弹出菜单按 Escape 关闭并恢复触发按钮焦点，按钮可用 Enter / Space 操作。Escape 不清空当前 Diff。
- 左右 Diff 的垂直滚动同步。弹窗使用明确的取消与确认按钮，并设置初始焦点；正式应用的项目加载使用系统文件夹选择器。

### 未加载项目

未加载项目时显示入口页，提供“加载本地项目”和“最近打开”列表。 此时隐藏顶部项目选择器，只保留中央加载入口，避免重复；加载项目后再显示顶部项目菜单。正式应用使用系统文件夹选择器，也可通过拖入已有仓库目录加载。

入口页不包含克隆、新建仓库、SSH、账号登录或远程连接入口。最近记录只展示项目名称和本地路径，点击后打开已有项目。清除最近记录只改变应用自己的记录，不删除本地仓库。

项目菜单提供加载其他项目、切换最近项目和关闭当前项目。关闭项目返回入口页，不修改仓库。目录不可访问、不是 Git 仓库或 Git 不可用时，在加载流程中明确提示，不能默默创建仓库。

### 更改

左侧默认显示全部有状态变化的文件，可切换到未暂存或已暂存范围。每个范围内按已跟踪和未跟踪分组，支持路径筛选。

更改面板和 Diff 详情的文件列表统一为单行：文件名在左，目录路径放在右侧，以较小字号和较淡颜色区分。路径过长直接截断，鼠标悬停显示完整路径。根目录文件只显示 `/`，不显示“项目根目录”文案。

已跟踪和未跟踪文件共用一个虚拟列表。已跟踪标题固定在顶部。未跟踪标题紧接最后一个已跟踪文件，超出可视范围时贴在底边，随列表向上滚动后停在已跟踪标题下方。折叠分组会收起文件行，保留当前文件选择和筛选后的数量。

移除标题栏手动刷新入口与 F5，改为低频自动核对；分支后紧跟上游分支名称、待推送（↑）和待拉取（↓）数量。统计来自本地远程跟踪记录，不自动 fetch；无上游或跟踪记录缺失时明确显示不可用状态。

Diff 长行统一自动换行，左右栏等宽，不提供横向滚动及其设置。图片文件按修改前 / 修改后并排预览，适应各自栏宽并保持比例；新增、删除时明确提示缺失的一侧。支持 PNG、JPEG、GIF、WebP、BMP、ICO、TIFF 和 SVG，GIF/WebP 显示首帧。

同一文件可以同时存在已暂存和未暂存变化。筛选计数以各自匹配文件计算，不应将分类计数相加当作唯一文件总数。“全部”视图即使净差异为零，也应保留仍有暂存区或工作区变化的文件记录。

Diff 应清楚显示比较对象，例如“HEAD → 暂存区”“暂存区 → 工作区”“HEAD → 工作区”。未跟踪文件单独识别，不能假设普通 git diff 会包含它们。

增删行数表示文本差异规模，不表示工作量或质量。二进制文件显示类型与状态，不伪造文本行数。统计尚未完成时显示计算状态。

### 分支浏览与切换

点击顶部当前分支展开可搜索的分支面板，按本地与远程分组。单击分支名称只改变历史浏览范围，顶部的实际检出分支保持不变；历史标题处显示当前浏览范围。

实际切换入口收进分支面板，与浏览动作区分。仅允许切换已有本地分支。远程分支仅提供历史浏览。

建议的首版切换策略：

- 存在未提交更改、冲突或进行中的合并、变基时，不执行切换。
- 不自动 stash，不强制覆盖文件。
- 分支由其他 worktree 检出时，提供查看对应 worktree 的入口。
- 执行前重新检查仓库状态，执行后刷新全部相关视图。
- Git 执行失败时显示实际原因，不自动降级为强制切换。

Git 本身允许部分带未提交更改的切换，上述条件属于保守的产品策略。仅凭文件变化或锁文件不能可靠判断 AI 是否仍在运行；切换功能不能承诺与外部 AI 的写入完全互斥。

### 远程分支

界面统一注明“本地记录”。远程跟踪引用、领先和落后数量，均基于当前本地已知对象与引用，不承诺反映服务器实时状态。

自动刷新只重新读取本地数据，不执行 fetch 或其他联网查询。外部 AI 更新引用后，面板读取变化。在项目入口的悬停提示中显示“本地读取时间”，不把它标成远程同步时间。

### 历史

历史提供两种共享选择与筛选状态的展示：

- 列表：提交标题、作者、日期、短哈希、分支或标签标识。
- 关系图：在列表旁绘制提交节点与父子连线，体现分叉与合并。

历史工具栏提供“…”显示设置菜单，使用带勾选状态的菜单项：

- **显示提交哈希**：独立显示或隐藏短哈希。
- **显示标签**：独立显示或隐藏 Git 标签，不与分支标识混为一项。
- **显示分支**：控制本地和远程分支标识的显示，不筛选提交、不改变关系图连线。
- **哈希、分支和标签显示在提交说明后面**：勾选后将这些信息整体放在说明后，取消后放在说明前。全部隐藏时不保留空白占位列。

默认显示哈希、标签和分支，并放在提交说明前。显示偏好在本机保存，关系图与列表共用；调整选项保持当前提交、文件、Diff、筛选范围和历史滚动位置。菜单支持方向键移动、Enter / Space 勾选、Escape 关闭并返回触发按钮；勾选后保持菜单打开，便于连续调整。只改变历史行的展示，不隐藏详情区的提交标识。

日期统一显示完整年月日与时间，格式为 `YYYY-MM-DD HH:mm`（例如 `2026-11-06 14:20`），不转换为“今天”“昨天”等相对日期。历史列表、提交详情和 Stash 使用同一格式；本地读取时间使用完整日期并保留秒。

选择历史提交后，下方直接展示提交说明、变更文件列表与首个文件的左右 Diff，第一个文件处于选中状态。点击文件切换对比内容，不需要额外操作进入 Diff。只有提交确实没有文件变更时才显示空状态；没有历史的空仓库不展示 Diff。切换列表与关系图时保留选中提交与文件。

关系图从提交与父提交标识构建，不解析终端中的 ASCII 图作为核心数据模型。滚动批次、浅克隆和筛选产生的缺失父节点应明确体现，不能绘制不存在的直接父子关系。

历史先展示首批提交，滚动接近已加载范围时按需加载后续批次，不等待遍历全部历史或计算精确总数。列表与关系图共用提交顺序、滚动位置和稳定的提交对象标识，只为可见行及少量缓冲行创建界面元素、绘制节点与连线。加载更多历史不得导致已有行跳动或重置选择；具体要求见“性能与大型仓库”。

合并提交默认与第一父提交比较，并显示该对象；其他父提交的选择可后置。根提交作为相对于空树的变化处理。空仓库使用独立空状态。

### 历史提交的文件 Diff

核心流程为“点击历史提交 → 展示该提交的变更文件 → 查看文件修改前后内容”。左侧为父提交中的文件，右侧为选中提交中的文件；不能用当前工作区内容代替历史版本。点击其他文件时更新同一详情区。

以下对象由所选内容自动确定，不提供任意分支或版本的组合选择器。

| 场景 | 左侧 | 右侧 |
| --- | --- | --- |
| 已暂存变化 | HEAD | 暂存区 |
| 未暂存变化 | 暂存区 | 工作区 |
| 当前净变化 | HEAD | 工作区 |
| 单次提交 | 父提交 | 选中提交 |
| Stash | 保存时基准 | Stash 内容 |

首版优先支持左右双栏、行号、增删颜色、基础语法高亮和上一处、下一处变化。统一差异模式、复杂行内高亮、全文上下文加载、多文件连续阅读均降低优先级。

读取 Diff 时固定比较对象；外部内容更新不能直接打乱用户正在查看的位置。可以给出普通更新提示，但不增加专门的审阅模式或审阅流程。

### Stash

展示序号、描述、保存时间、文件数量及差异。若 Stash 保存了未跟踪文件，应展示这些文件。不存在的内容不能用当前工作区文件代替。

读取详情时绑定具体对象标识，避免外部工具改变 Stash 列表后，序号变化导致显示错误对象。Stash 按仓库组织，不默认当作某个 worktree 的独占内容。

## 技术方案与可行性

### 已确认的技术栈

采用单进程原生桌面应用。系统 Git 子进程负责仓库访问，应用负责调度、数据转换、状态管理与展示。Windows 优先交付；各层保留跨平台边界。

| 层次 | 已采用方案 | 使用范围 |
| --- | --- | --- |
| 语言与构建 | Rust stable + Cargo | 在实施时固定兼容的工具链与依赖版本，提交 Cargo.lock，发布使用锁定依赖构建 |
| 界面与后端 | gpui-kit 默认后端 | 使用 Kit 匹配的上游 GPUI 快照；gpui-fast 作为可选 Cargo feature，默认关闭 |
| 工程组织 | 按更改、历史、Stash、设置等能力组织 Rust 模块 | 共用 Git 执行、刷新和配置服务；Git 数据解析与图布局算法可脱离 UI 测试，复杂后再拆分 crate |
| UI 状态 | GPUI Entity、事件与任务机制 | 保存项目、浏览范围、选择与加载状态；后台传递有版本的数据结果，UI 短时应用更新 |
| Git 引擎 | 用户已安装的系统 Git | 直接传递子进程参数；不内置 Git，不使用 git2、libgit2 或 gix |
| 后台执行 | GPUI 任务机制 + async-process | 异步管理 Git 子进程，计算密集工作交给后台执行器；首版不额外引入 Tokio 运行时 |
| 状态刷新 | 低频后台轮询，前台约 15 秒、后台或失败后约 60 秒 | 串行查询，复用未变化历史，保留阅读位置；无手动刷新 |
| 配置持久化 | serde + serde_json + directories | 在平台应用配置目录保存带版本字段的 JSON；首版不引入数据库 |
| 查询缓存 | 有容量限制的内存缓存 | 对象详情与补丁按仓库、对象和查询条件缓存；可变状态按刷新版本失效 |
| 文本 Diff | GPUI Kit Diff，禁用语言语法高亮 | 双栏自动换行及红绿增删标色，后台解析，避免全局语法缓存 |
| 提交关系图 | 自行实现提交列布局 + GPUI 绘制 + 虚拟列表 | 保留跨批次布局状态，按可见区域绘制，不使用整张历史图作为一个巨大界面树 |
| 日志与错误 | tracing + thiserror | 结构化记录命令耗时、队列、刷新与错误；错误保留实际 Git 原因，日志不默认记录源码或补丁全文 |
| 验证方式 | cargo test、真实 Git 临时仓库集成测试、Windows release 性能测试 | 覆盖解析、提交图、并发刷新、工作目录及 UI 交互；运行性能与编译速度分别评估 |
| 分发 | GitHub Actions 构建，GitHub Release 发布 ZIP 与 Inno Setup 安装包 | 提供软件自动更新；GitHub 检查更新被限流时切换 Release 镜像源 |

### gpui-kit

使用 Rust 与 gpui-kit 构建原生界面。截至本次调研，官方文档版本为 0.9.0。现有 Diff 组件支持左右双栏、折叠、语法高亮等基础能力；官方 tig 示例通过系统 Git 浏览提交与补丁，可参考其后台读取和过期请求处理方式。

默认后端作为功能和性能验收基线。通过应用的可选 feature 转发 `gpui-kit/gpui-fast`，保留后续对比验证入口；不以启用 gpui-fast 作为满足流畅度要求的前提。具体依赖版本在最小运行验证通过后固定，不混用不匹配的 GPUI 核心版本。

Diff 组件负责展示应用提供的补丁，不负责查询仓库或计算版本差异。补丁中未包含的上下文不会由组件自动恢复。

普通列表、文件树、分栏采用现有组件。提交关系图采用自有布局及绘制，跨滚动批次保存未连接的父对象与列分配状态。

界面支持能力已经有官方资料与示例作为依据；大型仓库性能、Windows 渲染和实际打包兼容性需要在实施阶段验证。

### 系统 Git

不内置 Git，不安装 Git，不使用 libgit2、git2、gix 等第三方 Git 实现库操作仓库。此约束针对 Git 引擎，不排斥 gpui-kit 或必要的普通工具依赖。

启动时检测 PATH 中的 Git，并支持指定用户已有的 Git 可执行文件路径。展示检测结果和版本。未找到或版本不满足能力要求时，仅提示原因、允许重新检测，并提供 [Git 官方安装页面](https://git-scm.com/downloads)。

通过子进程直接传递参数，不拼接 shell 命令。状态采用机器可读格式，路径采用明确的边界和分隔符，正确处理中文、空格及特殊字符。引用先解析为明确对象，避免异步加载时分支移动造成内容混淆。

读取命令包括 status、for-each-ref、log、show、diff、stash list、stash show、worktree list 等。分支切换独立于读取通路，不设置任意 Git 命令执行入口。

所有命令经过统一执行层，集中管理工作目录、参数、环境、标准输出与错误输出、退出状态、超时和取消。大输出采用流式读取与有界批次，不能等完整输出进入内存后才开始处理；同时排空输出管道，避免子进程互相等待。Windows 后台 Git 进程不弹出终端窗口。

只读任务过期或超时时，停止后续处理，并按策略终止、回收对应子进程；丢弃 UI 任务不等于子进程已经退出。分支切换采用独立的应用级任务持有到完成或明确失败，不随文件选择、详情关闭而取消，不直接套用读取任务的强制终止策略。执行过程中只限制受影响的操作，其他界面仍可响应。

### 刷新与数据一致性

- Git 查询和补丁解析在后台执行，界面不等待阻塞式仓库扫描。
- 采用低频后台轮询：前台约 15 秒、后台或失败后约 60 秒，一轮结束后再计时，不堆积请求；引用不变时复用历史。不依赖递归文件监测，也不提供手动刷新。
- 按工作区状态、引用与历史、当前详情分别标记失效；单个文件变化不自动重读全部历史及全部补丁。
- 优先刷新当前项目，其他项目采用较低频率更新。窗口不可见时降低非必要查询与预取，回到前台后核对状态。
- 监测工作目录、真实 gitdir 与 common dir 的相关变化；事件丢失、监测失败或目录重建时可重新注册并退回核对机制。
- 每个请求携带仓库与 worktree 身份、浏览范围、对象标识、选择与数据版本；结果回到 UI 时再次校验，丢弃过期结果。
- 只读状态查询禁用可选锁，减少与外部 Git 操作争用。
- 通过 Git 查询真实 gitdir 与 common dir，兼容 worktree 和 .git 文件形式。
- 默认禁用外部差异程序和 textconv，避免查看时启动用户配置的额外工具。
- 对部分克隆禁用隐式对象获取；本地对象缺失时提示内容不可用，不自行联网补齐。

实际切换分支可能触发 Git hooks、过滤器等用户配置行为，因此不能将整个程序描述为绝对只读或把切换描述为无副作用。不得为了绕过失败而静默修改仓库配置。

### 数据存储

项目清单、显示偏好、最近选择等通过 serde_json 保存在 directories 定位的应用配置目录。Windows 配置路径明确为 `%APPDATA%\githly\config.json`（Roaming AppData），不放在可执行文件或项目旁边。配置包含格式版本，在后台按顺序写入，通过临时文件替换等方式避免留下半写文件。配置损坏或版本不兼容时显示错误并保留原文件，不静默覆盖。缓存不写入项目源码目录或 Git 引用。

首版不复制 Git 历史到 SQLite 等数据库。缓存同时设置条目数与字节容量限制，按需淘汰；大补丁不能仅按文件个数计费。不可变对象缓存以仓库、完整对象 ID 及影响输出的选项为键；工作区、暂存区、引用列表和 Stash 序号属于可变状态，按查询版本失效。关闭项目后释放其监测器、后台任务与不再使用的数据。

不保存审阅进度、文件已读状态、审阅检查点或本地活动时间线。首版不记录每次文件编辑快照。

## 性能与大型仓库

### UI 线程与后台任务边界

以下为实现约束，适用于所有功能及默认后端：

- UI 线程只处理输入、轻量状态更新、可见元素的布局与绘制。Git 执行、同步文件 I/O、目录扫描、历史解析、补丁解析、高亮、批量排序和提交图布局都必须离开 UI 线程。
- `async` 不等于在后台运行。GPUI 的前台 `cx.spawn` 可等待结果并更新 Entity，耗时计算必须通过后台执行器处理；不能在前台异步任务里执行长时间同步循环。具体 API 以锁定版本为准。
- 不在渲染函数、点击或滚动回调中等待进程退出、读取文件、等待线程结束或持有可能长时间阻塞的共享锁。渲染不重新解析补丁、构造完整历史模型或复制整份提交集合。
- 后台结果批量提交到 UI，每批处理量有上限，超出则分多次更新。禁止每解析一个提交或收到一个文件事件就单独触发重绘；大型集合的释放也不能形成明显主线程停顿。
- Git 子进程与 CPU 任务均有并发上限，消息队列与待处理批次有容量限制。重复刷新合并，过期读取取消，避免大量后台工作争抢 CPU、磁盘和内存后间接拖慢 UI。
- 当前交互请求优先于历史预取和非当前项目刷新。任务等待时显示局部加载状态，已有内容保留；用户仍可打开菜单、滚动已加载内容、切换选择和调整窗口。
- 每个运行任务有明确所有者和结束条件。只读任务取消、关闭项目和退出应用应释放相应资源；分支切换按独立生命周期处理。

### 历史虚拟渲染与分批加载

**虚拟渲染和分批读取必须同时实现。** 仅将 19,685 条提交全部读入并解析，再套用虚拟列表，不满足首次加载与后台负载要求。

1. **按需取数。** 首批只获取绘制列表需要的提交元数据，包括对象 ID、父对象 ID、标题、作者和时间。用户选中提交后，按需读取正文、变更文件和首个文件的 Diff。
2. **优先等高行。** 历史使用紧凑固定行高与截断标题，完整说明放在详情区，优先选用 GPUI 的等高虚拟列表能力。需要变高内容时再采用 Kit 的 VirtualList，避免为了测量行高遍历完整历史。
3. **仅绘制视口。** 列表文字与提交图共用可见行范围和少量缓冲行。跨越视口的连线按范围裁剪；滚动不创建全部历史的节点，也不重新计算整个提交图。
4. **稳定加载会话。** 一次历史浏览将引用解析为固定对象集合，并固定排序与筛选条件。外部新提交或分支移动触发更新提示或新一轮刷新，不能直接改变正在加载的批次边界。使用 Git 拓扑顺序组织父子关系。
5. **保留图布局边界。** 后台按批次计算列分配，保存尚未接上的父对象与跨批次连线状态。加载下一批后能正确延续合并与分叉，返回查看前批次时保持既有布局。浅克隆、筛选或对象缺失明确显示截断关系。
6. **有界预取。** 滚动接近已加载范围时预取有限批次，未就绪时显示加载占位。快速滚动与切换分支不堆积无限请求；深页读取不能反复从 HEAD 全量遍历而形成累计性能退化，具体批次、游标或流式读取策略通过基准验证。
7. **有界内存。** 历史元数据、图布局和补丁分别计量并设置预算。远离视口的数据页按需淘汰，保留重载所需的定位信息与布局检查点；淘汰后仍能返回旧位置，不把缓存上限变成历史条数上限。
8. **保留阅读位置。** 同一浏览范围刷新时，以提交 ID 和行内偏移恢复滚动锚点及选择。切换项目或浏览范围后，等待用户选择提交。列表与关系图互切复用数据与选择。历史筛选在后台执行。

### 更改列表、Diff 与刷新成本

- 文件清单、提交变更文件和长分支列表同样按数量采用虚拟列表；路径过滤对输入合并处理，较大集合在后台计算。
- 更改状态先显示，增删行数异步补齐。统计未完成时显示计算状态，不能为了精确统计阻塞整个页面；普通状态刷新不预加载所有文件内容。
- 默认首个文件的 Diff 独立加载，自动选择后在 Diff 区域显示加载反馈，完成后替换为内容，不增加需要再次选择文件的摘要步骤，也不等待全部文件补丁。快速切换文件时，只允许当前选择对应的结果进入详情区。
- 大补丁采用大小、行数与处理时间限制，长行可降级高亮；二进制、超限或缺失内容提供明确说明与按需操作。不能把截断内容展示为完整差异，也不能依赖 UI 线程处理超限内容。
- 保存与复用已解析的 Diff 状态，绘制期间不重新解析。上下文、折叠与语法着色按实际展示范围控制成本，具体能力以组件验证为准。
- 大型仓库还包含文件数量多、未跟踪文件多、分支多、worktree 多及单次改动大等情况，不能只用提交条数推断性能。

### 性能基准与验收目标

使用 Windows **release 构建与默认后端** 测试，记录硬件、操作系统、显示刷新率与缩放、Git 版本、仓库规模、冷/热缓存条件。Debug 构建和少量 HTML 示例数据不能作为性能达标依据。19,685 条提交的真实仓库路径与测试环境在实施时确认，当前尚未执行该基准。

| 维度 | 首轮目标与验证方式 |
| --- | --- |
| 真实历史基线 | 在至少含 19,685 条提交的现有项目中浏览到最早记录并往返滚动，验证无漏项、重复和错误父子连线；后台刷新期间仍可交互 |
| 扩展规模 | 另准备至少 100,000 条提交的生成仓库进行压力测试，包含合并与分叉；用于观察扩展趋势，不把测试规模声明为产品上限 |
| 首次可用 | 在约定基准机上，打开项目后 1 秒内出现可交互界面与加载反馈，首批历史热缓存目标 1 秒内、冷缓存目标 3 秒内；全部历史不在首屏关键路径上 |
| 输入响应 | 后台扫描、解析和加载期间，点击、键盘与菜单的可见反馈延迟 p95 目标不超过 100 ms；数据完成时间单独记录 |
| 滚动帧耗时 | 以 60 Hz 为首轮基线，持续滚动的帧间隔 p95 目标不超过 16.7 ms、p99 不超过 33.3 ms；定位应用自身造成的超过 50 ms 的主线程长任务，高刷新率另外记录 |
| 虚拟化有效性 | 记录实际创建、布局和绘制的行数，确认随视口及缓冲范围变化，不随历史总条数线性增加；列表与关系图分别验证 |
| 后台负载 | AI 持续写入、连续刷新和快速切换提交时，进程数、队列长度、预取批次均不超过配置上限，过期结果不覆盖新选择，连续事件不造成刷新饥饿 |
| 内存与回收 | 记录峰值内存及各缓存字节数；重复打开/关闭项目、往返滚动和切换 Diff 后应趋于稳定，任务、监测器与缓存可释放，不要求进程工作集立即回到初始值 |

表中的毫秒级目标是首轮工程预算，尚未实测。具体基准机、采样方法、缓存预算和阈值需在最小实现中校准并记录；校准不能取消“后台工作不阻塞 UI、虚拟渲染、按需加载和有界资源”的要求。首次结果建立基线，后续提交保留可复现的性能回归场景；同时记录 Git 耗时、队列等待、解析/布局、UI 更新、帧耗时和内存，不能仅凭平均 FPS 判断流畅。
