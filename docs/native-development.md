# Githly 原生开发进度

当前版本为 0.1.1，优先在 Windows x64 开发和验证。

## 技术与构建

- Rust 1.99.1，MSVC 工具链；GPUI Kit 0.9.0，默认 GPUI 后端。
- 系统 Git CLI，异步读取；不内置 Git，不引入 libgit2。
- 日常使用 `cargo build` / `cargo run`，仅在需要发布构建时添加 `--release`。
- Cargo 使用默认 CPU 并发，没有固定 jobs 限制。
- Windows 图标和版本信息由 `build.rs` 嵌入 EXE；主线程预留 8 MiB 栈，页面按需提交。
- `vendor/gpui-component` 保留 Diff 布局、文本选择和分段控件的必要补丁，详见其中的 `PATCHES.txt` 与 `LICENSE-APACHE`。

## 读取限制

常规 Git 查询的标准输出上限为 8 MiB，错误输出上限为 64 KiB，读取超时为 20 秒。刷新时逐条读取引用并计算摘要，分支列表和单条引用各限 8 MiB。单文件文本 Diff 上限为 2 MiB，未跟踪文本上限为 1 MiB。超限显示错误。

图片单侧原始文件上限 8 MiB，位图解码预算 64 MiB，单边最大 16,384 像素；预览最长边不超过 1,600 像素。SVG 不读取外部文件引用。

这些阈值用于控制读取和渲染成本，并非完整的大型仓库性能承诺。

## 自动刷新与滚动续载

Git 查询、历史解析、图布局和历史搜索在后台执行；没有变化时不替换仓库快照，引用不变时复用历史与图布局。滚动至距已加载末尾约半屏时续载，每批 100 条，共享已有批次的字符串和图数据；同一浏览会话沿一个 Git 输出流继续读取，不对每个后续批次从 HEAD 重扫。每批输出限 8 MiB、读取超时 20 秒，最多一个续载任务；失败后至少等待 60 秒重试。

当前所选提交独立保存，外部提交、重置或切分支不会将 Diff 错配到新列表索引。历史变动保留滚动锚点；浏览旧历史期间先提示有更新，回到顶部后自动应用新历史。工作区 Diff 保留打开时的快照，界面明确说明重新选择文件查看最新内容。

关闭 / 切换项目取消刷新计时器、读取及搜索任务，终止并回收历史 Git 子进程，释放仓库批次、分支列表、Diff 与图片资源。已加载历史随实际浏览量增长，尚未实现远离视口批次的淘汰与磁盘重载；此项与大型仓库性能验收继续保留在 TODO。
